Architecture explained in plain English

How decinav turns decisions into dependable project data

The tool keeps Architecture Decision Records as strict Markdown files, checks their relationships like a data graph, and derives a Mermaid view that people and CI can trust.

The shortest useful mental model

Humans or a local AI propose ADR text. The AI also produces read-only analysis. Deterministic Python validates repository writes and every machine-readable AI result.

Markdown is the sourceEach ADR is readable by people and machines.
Relationships are dataDependencies and supersessions carry reasons.
AI output is untrustedProposals and analysis cannot bypass deterministic checks.
The graph is derivedREADME Mermaid can always be regenerated.

Mermaid + POSIX hook

Safe source bundler

Selects only supported inputs; excludes source code, secrets, dependencies, lockfiles and oversized files for baseline discovery.

Local AI process boundary

Runs the configured CLI without a shell. Prompt travels by argument, temporary file, or stdin; no REST API is built into decinav.

Minimized intelligence context

impact and query send only validated frontmatter plus Context and Decision blocks; returned ADR references are checked before display.

Git commit-msg policy

When staged src/ or infra/ changes exist, require [ADR-XXXX] or [skip-adr]; warn-only mode supports brownfield adoption.

Trust boundary Local AI stdout is untrusted input. Writes require full prospective graph validation; read-only intelligence rejects malformed schemas and unknown ADR references.

The shared safety gate

No AI or manual shortcut can weaken these repository invariants.

✓ Exact V1/V2 frontmatter fields
✓ Unique IDs and matching filenames
✓ Existing relationship targets
✓ No causal relationship cycles
✓ V2 links include a reason
✓ Contiguous generated IDs
✓ No file overwrite
✓ Full future graph checked pre-write

What each command actually does

Inputs on top, concrete state changes on the bottom.

init

Prepare a Git project

Creates docs/adr/README.md and installs a strict or warning-only commit-message hook without silently replacing foreign hooks.

OUTPUT → directory + local Git policy
new

Create one proposed ADR

Allocates a deterministic ID, records relationship reasons, writes a strict V2 template, and opens $EDITOR.

OUTPUT → one new Markdown ADR
graph

Derive a human view

Analyzes all readable ADRs and updates the managed Mermaid block globally, around a focus ADR, or for one domain.

OUTPUT → README Mermaid graph
validate

Act as the CI gate

Aggregates schema, filename, duplicate-ID, dangling-link and cycle failures; exits with status 1 if any exist.

OUTPUT → pass/fail + all issues
baseline

Create the one Day 0 ADR

Reads only safe structural context, asks a local AI for exactly ADR-0001, validates it, writes it, then regenerates the graph.

OUTPUT → validated baseline + graph
ingest

Extract atomic past decisions

Bundles supported informal documents, provides the existing graph to the local AI, validates a contiguous batch, publishes it, then regenerates.

OUTPUT → validated ADR batch + graph
impact

Estimate PRD blast radius

Compares a proposed PRD with minimized ADR evidence, validates every referenced ID, and optionally emits a red, blue, and green Mermaid visual diff.

OUTPUT → read-only Markdown impact report
query

Ask the architecture

Uses the same minimized evidence and requires inline [ADR-XXXX] citations for traceable semantic answers.

OUTPUT → cited Markdown answer
ui

Use the browser workbench

Hosts a token-protected loopback UI over the same onboarding, validation, impact, and query workflows with an offline SVG graph.

OUTPUT → local interactive workbench

Technology inside the tool

Each dependency has a narrow job; the safety-critical behavior stays explicit in application code.

Python 3.11+

Core runtime, filesystem handling, subprocess control, dataclasses, temporary staging, and atomic operations.

Application language

Typer

Defines commands, arguments, options, prompts, help output, colors, and exit codes.

CLI interface

PyYAML SafeLoader

Reads YAML without constructing arbitrary Python objects; decinav adds duplicate-key and exact-field checks.

Strict frontmatter parsing

Markdown + YAML

Keeps decisions reviewable in Git while exposing typed metadata to the program.

Durable data format

Mermaid

Turns the validated causal relationships into a clickable, domain-colored flowchart embedded in README.

Derived visualization

Git + POSIX shell

Discovers the real worktree and installs a dependency-free commit-msg policy in Git's effective hooks directory.

Workflow enforcement

Local AI CLI adapter

Runs Codex, Claude, Sol, or another configured process through argument, prompt-file, or stdin transport—never through a shell.

Semantic extraction and analysis boundary

Python HTTP server + SVG

Hosts the loopback-only browser UI, authenticates local JSON actions with a random token, and renders decision graphs without an online dependency.

CLI-free local workbench

pytest + Hatchling

The test suite proves behavior; Hatchling packages the src/ layout and exposes the decinav executable.

Verification + packaging

Where truth lives

This distinction is what keeps the design understandable when a step fails.

Source of truth: ADR Markdown

The decision text and V2 metadata in docs/adr/*.md are durable project state.

Derived state: README graph

The Mermaid block is a view over ADR relationships. If it is stale or deleted, decinav graph rebuilds it.

Untrusted proposal: AI stdout

AI output is never accepted because it sounds plausible. Deterministic code must prove its envelope, schema, IDs, links, and graph are valid.
