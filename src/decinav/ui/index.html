How to read this graph

  • Each box is one recorded decision about how the system is built: what was decided and why. Engineers call these ADRs.
  • Arrows go from an earlier decision to a later one. Solid: the later decision builds on the earlier one. Dashed: the later decision replaces it.
  • Status dot: amber = proposed, not yet approved · green = accepted · violet = baseline, the starting snapshot · grey = superseded or deprecated.
  • Freshness glyph comes from Git, not from a model: ● fresh = nothing changed since it was checked · ◐ aging = the project changed since · ▲ sources changed = the documents it came from changed · ? unknown = never checked.
  • The left edge color is the area: frontend, backend, infrastructure, data, system.
  • Large projects open collapsed by area. Click an area to expand it, search for a decision, or pick one from the list below. The counter always says how many are shown.
  • Keyboard: Tab or arrow keys move between decisions · Enter opens one · F focuses on its neighbours · Esc closes the panel.
